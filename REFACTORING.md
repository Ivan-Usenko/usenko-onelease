## Помічені проблеми

| № | Проблема | Наслідок |
|---|----------|----------|
| 1 | файл відкривається без with | дескриптор не закривається |
| 2 | цикл while з ручним лічильником | ризик нескінченного циклу |
| 3 | побудова рядка посимвольно | зайвий код там, де достатньо методу lower() |
| 4 | порівняння з None через != | має бути is not None |
| 5 | except без типу | приховує будь-яку помилку, зокрема друкарську |
| 6 | запис у список замість сутності | res[2] нічого не пояснює читачеві |
| 7 | дедуплікація вкладеним циклом | складність O(n<sup>2</sup>) замість O(n) |
| 8 | ручний підрахунок у словнику | готовий інструмент Counter не використано |
| 9 | print усередині функції | неможливо повторно використати й протестувати |
| 10 | одна функція робить чотири справи | не тестується, не читається, не розширюється |
| 11 | імена f, d, t2, res2, st | код неможливо зрозуміти без розшифрування |
| 12 | відсутні анотації типів | невідомо, що приймає й повертає функція |
| 13 | Немає break у внутрішньому циклі дедуплікації | Після found = True цикл усе одно доходить до кінця |
| 14 | found == False замість not found | важче читати |
| 15 | for x in range(len(...)) замість ітерації за елементами | зайвий індекс з яким доводиться мати справу |
| 16 | Немає перевірки наявності ключів | item["title"], item["company"], item["city"] дадуть KeyError, якщо ключа немає |
| 17 | Ключ дедуплікації неповний або ненормалізований | yазва нормалізується, а company ні, тому "Київ-Дім" і "київ-дім " вважатимуться різними. Місто в ключ не входить. |
| 18 | Ціна "6500 грн/місяць" мовчки стає 0. | втрата даних |

## Зміни
1. Тепер при парсингу оголошення з нечисловим значенням ціни, замість значення 0 тепер значення None

## Примітки
1. Оскільки RentalListing оголошена як frozen, дедуплікацію в onelease.pipeline.deduplicate можна виконати й одним виразом set(items) – але тоді втрачається початковий порядок записів.
2. read_rows (завантажує всі дані з файлу в список одразу) - використовує 112.6MB оперативної пам'яті та займає 1.97 с, в той час як read_rows_jsonl (використовує генератор для почергового завантаження) - використовує 0.2МБ та 1.44 с.
