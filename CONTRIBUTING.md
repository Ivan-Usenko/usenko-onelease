## Іменування гілок
| Перфікс | Призначення | Приклад |
| --- | --- | --- |
| feature/ | нова функціональність | feature/vacancy-parser |
| fix/ | виправлення помилки | fix/empty-title-crash |
| refactor/ | зміна структури без зміни поведінки | refactor/split-domain-module |
| docs/ | документація | docs/readme-quickstart |
| chore/ | службові зміни, конфігурація | chore/update-ruff-config |

## Формат повідомлень комітів
Повідомлення коміта пишеться в наказовому способі й описує дію, а не файл: add vacancy
normalizer, а не «правки» чи «файл 3». Рекомендована структура заголовка – тип: короткий
опис (до 60 символів), за потреби – порожній рядок і абзац пояснення, чому зміна потрібна.

## Вимоги до pull request
Повідомлення до pull request мають бути написані за наступним шаблоном:
```
## Що зроблено
-
## Навіщо
-
## Як перевірити
1.
## Чек-лист автора
- [ ] ruff check і ruff format пройдені
- [ ] коміти атомарні, повідомлення осмислені
- [ ] секрети й тимчасові файли не потрапили в діф
```
